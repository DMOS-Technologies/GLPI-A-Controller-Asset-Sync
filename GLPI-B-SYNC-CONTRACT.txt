Add the following feature to the plugin:

- Implement the Asset Sync Agent endpoint on GLPI B at POST /plugins/assetsyncagent/front/sync.php, relative to the GLPI installation root. Accept application/json. Controller A uses the same origin as its saved GLPI B legacy REST URL. Reuse the existing API client, source-address allowlist, service account, and token pair.
- Require App-Token and Session-Token headers. Controller A obtains the session through the existing /apirest.php/initSession and closes it with /killSession. Apply GLPI's legacy API authentication, including the App-Token, source address, and bound session. Restrict this endpoint to the dedicated Controller integration account and its API client. Use the service profile's permitted entities. Keep this endpoint independent of browser cookies, and keep credentials out of URLs, responses, and logs.
- Probe and apply receive operation, itemtype, entity_id, and serial. Match the serial only among nondeleted, nontemplate assets of that exact GLPI B itemtype and mapped entity. Treat entity ID 0 as valid. Limit itemtypes to GLPI's registered asset catalog and require serial support. Reject ambiguous matches and prevent concurrent creates for the same type, entity, and serial.
- The read-only changes operation receives itemtype, entity_id, cursor, and mapped B field descriptors in fields. A null cursor starts at current history without replaying past edits. Return {"ok":true,"cursor":123,"changes":[{"serial":"EXAMPLE","field_ids":[1]}],"more":false}. Include only authorized assets and mapped fields changed since the cursor. Use GLPI's field audit history, including native Notes and Fields plugin events. Exclude history emitted by the Agent's own sync writes. Return event metadata only. Controller A queues those asset and field IDs and processes them in subsequent runs.
- Probe request includes fields, an array of field descriptors. Return HTTP 200 with {"ok":true,"exists":false} when the serial is absent. For an existing asset return {"ok":true,"exists":true,"asset_id":123,"values":{"1":{"value":"example","modified_at":1730000000,"kind":"text"}}}. The values object uses B search-option IDs. Return the destination kind as text, boolean, integer, number, date, datetime, dropdown, dropdown_list, or item. modified_at is the field's actual GLPI history timestamp in Unix seconds, or null when unavailable. A record-level edit timestamp must not stand in for an individual field's timestamp.
- Each descriptor has integer id, table, and field from B's search options. linkfield, uid, datatype, name, and source can also be present. Resolve each descriptor against B's current local catalog and Fields permissions. Handle native columns and Fields plugin columns through GLPI's models, honor read-only fields, and scope Fields containers to their permitted entities. Translate portable dropdown values by name in the destination scope. GLPI A's numeric foreign keys have no meaning on B.
- For GLPI native custom assets, resolve exposed search options to their local custom field definitions and write through the model's custom_* form fields. Do not transfer a raw custom_fields JSON object, because definition IDs can differ on A and B.
- Support GLPI Notes through search option 200 (glpi_notepads.content) as kind "notes". Return a sorted list of distinct, sanitized rich-text bodies from the exact asset's Notes records and the newest note-level edit time. Require the destination's GLPI note permissions. Append only bodies that are missing, preserve existing Notes, and create copied notes with ticket visibility disabled. Controller A can request additions in both directions when the newest edit cannot be determined. Strip embedded images and source-local document links. Do not transfer note IDs, authors, or attachments.
- Read a single dropdown as its portable display label, preferably the full path for a hierarchical dropdown. Read multiselects as arrays of labels. For text-to-dropdown and dropdown-to-dropdown, prefer a unique full-path match and otherwise accept a unique visible leaf label. Apply GLPI's entity visibility rules, including ancestor options shared with child entities. Report an error for missing or ambiguous matches. For dropdown-to-text, use the label, or join a multiselect's labels with a comma and space. For text-to-multiselect, a single label or an explicit JSON array of labels is accepted. A multiselect with multiple values cannot fit a single-select field. Never copy numeric option IDs between databases or create dropdown entries implicitly.
- Normalize writable fields by the destination's actual field type. Preserve text, multiline text, rich text, and URL content using native GLPI input handling. Represent yes/no as JSON true or false, and accept yes/no, true/false, on/off, and 1/0 input. Preserve decimal precision. Use YYYY-MM-DD for dates and YYYY-MM-DD HH:MM:SS in UTC for datetimes. Accept ISO date/time inputs and reject invalid or ambiguous conversions. Use the destination's native validation for formats and constraints.
- Represent a Fields plugin GLPI item reference as {"itemtype":"Computer","label":"Example","serial":"ABC-123"} where serial is present for identifiable assets. Validate the field's configured allowed itemtypes and look up that item by serial where supplied, otherwise by its unique name in the destination scope. Write its itemtype and local item ID together. Plain text may resolve an item reference by name when the field allows exactly one itemtype. Preserve explicit clearing and reject attempts to set a structural header, an isolated reference type, or generated read-only metadata.
- Apply request includes create (boolean), expected_asset_id (the B asset ID from probe on update, null on create), values (array of {"field":<descriptor>,"value":<value>}), expected and initial (arrays of the same shape), and initial_native (a column-to-value object, or an empty array when there are no initial fields). On update, match expected_asset_id as well as type, entity and serial, reject mismatches against expected, and write only the submitted mapped values. An empty values list can acknowledge that expected still matches for a B-to-A write. Reject a create if a matching asset appeared after probe, and reject an update if the asset no longer matches.
- On create, seed populated portable columns from initial_native, named native dropdown values from initial, and mapped fields from values. Use entity_id and serial from the request envelope. Validate columns and values against the GLPI B asset model, and give explicit mapped values precedence over initial fields. Exclude identity, lifecycle, security metadata, foreign IDs, and unmapped instance-specific references from the initial native copy. Reject invalid or unresolvable submitted values without partial writes.
- Return HTTP 200 with {"ok":true,"asset_id":123} only after all writes succeed and commit. Include applied_values keyed by B search-option ID with the actual portable value for each mapped field written, so the Controller can record the canonical dropdown label or path. Return {"ok":false,"error":"<code>"} for failures, with a suitable HTTP 4xx or 5xx status. Use ambiguous_serial for duplicate matches, asset_changed for revised expected values or a create/update race, asset_identity_changed for lost serial/entity identity, asset_busy for a lock conflict, field_unavailable or field_read_only for unsupported descriptors, reference_unavailable for a missing or ambiguous destination dropdown value, and entity_not_allowed for an out-of-scope entity. Errors must exclude submitted values and credentials.
- If a request sets include_error_details to true, a field error may include a safe, user-facing reason and the B search-option field_id, or the column for a native value sent in initial_native. A group error may include reason, group, and the field_ids or native columns submitted to that group. A batch returns these details on the corresponding result. Controller A looks up attempted values in the original request and hides sensitive values in the display.
- Controller A owns the routes, field directions, timestamp comparison, scheduling, batch limit, and sync status. Agent B performs the requested serial lookup and validated write, then returns its result in the same HTTP request. Use Controller A's one-minute cron as the trigger.
- Controller A puts failed operations in Failed Syncing. Retry Sync queues the asset for a later scheduled batch, and the Controller probes again before attempting a new write. Agent B must support safe replay after a timeout or lost acknowledgement. A retry must not duplicate an asset or overwrite a newer value from a stale request. Send a success acknowledgement only after commit, and return stable non-sensitive errors for unreachable dependencies, conflicts, validation failures, or database errors.
- Verify from the Controller container that a missing serial can be created once, a retry cannot create a duplicate, an existing asset updates only submitted mapped fields, a B-to-A probe returns mapped values and accurate per-field history, and native-to-Fields mappings work for authorized containers. Test text-to-dropdown, dropdown-to-text, dropdown-to-dropdown with different numeric option IDs, dates, datetimes, yes/no, and invalid or ambiguous lookups. Verify that stale expected values, conflicting serials, unauthorized entities or credentials, and attempts to rewrite serial or entity are rejected.
